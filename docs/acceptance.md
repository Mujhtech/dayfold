# Core acceptance map

This maps all 185 IDs in section 27 of [the brief](../NativeCalendar_Agent_Brief.md). “Passed” refers only to the named deterministic test or observed manual record. “Partial” and “unverified” prevent a full Core/beta acceptance claim. Live Google behavior is never inferred from the fake provider.

Tests link directly to their source; all named normal-suite tests passed on 6 November 2026. The performance test ran separately in Release. MAN records are in [verification.md](verification.md). Source labels link to implementation, not proof of successful execution.

Missing evidence/prerequisites:

- **G:** No owner Desktop OAuth configuration, user-authorized disposable Google accounts/calendars or approved invitation recipients. Live Google acceptance is blocked.
- **P:** Platform scenario lacks a completed manual record; XCTest UI runner did not initialize with Developer Mode disabled. Owner chose to retain current permissions. A partial manual record is not a passed UI suite.
- **N:** Actual UserNotifications authorization, delivery and action checks have not been performed. Demo intentionally schedules no system notifications.
- **L:** Actual login-item approval/relogin scenario has not been exercised.
- **H:** Required physical display/sleep/network environment, minimum macOS/Intel or clean user profile was not exercised.
- **D:** No Developer ID/notarization configuration or authorized distribution artifact.

P/N/L/H include verification gaps, not claims that all such checks are technically impossible. No missing test is silently marked passed. M12 extensions are Not enabled.
