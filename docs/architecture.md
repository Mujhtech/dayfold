# Architecture

The existing Xcode target owns the native bundle and views. CalendarCore is a Swift 6 package with Sendable domain values, a GRDB repository actor, Google REST DTOs, mutation/synchronization state machines, date calculations, parser, layout algorithms, and deterministic fixtures. CalendarPlatform isolates AppAuth, Keychain, UserNotifications, hotkey registration, login items, and the process ownership lock.

`AppModel` creates one repository, provider, synchronization coordinator, dispatcher, and platform adapters per store. Main window, companion, inspector, search, and editors observe repository revisions. SQLite/network work happens outside MainActor; presentation state is isolated to MainActor. Requests capture generations and calendar write epochs, and per-calendar leases coordinate network mutations with read publication across actor suspension points.

Data identity is account + opaque calendar ID + opaque event ID. Account deduplication uses issuer and verified Google subject; email is display data. All-day civil dates and absolute timed intervals are distinct. Unknown Google JSON is preserved; write payloads contain explicit changed fields, never a narrow reconstructed resource PUT.

The database holds accounts, calendar metadata, resource and occurrence records, cursors, staging, complete-window membership, drafts, mutations, conflicts, preferences, notification ledger, and FTS documents. Schema v5 includes indexed FTS documents (v2), visible-range indexes (v3), recurrence cancellation lookup (v4), and closed-draft markers that reject delayed autosaves (v5). A v1 database fixture verifies migration of drafts, outbox, and search. Accepted writes and draft removal commit transactionally; pending records produce optimistic projections. A complete remote reset never clears local intent.

Resource queries use `singleEvents=false`, `showDeleted=true`, `showHiddenInvitations=true`, `maxResults=1000`, and no date/search filters. Occurrence queries use bounded timeMin/timeMax, `singleEvents=true`, `orderBy=startTime`, and no sync token. Empty pages with nextPageToken are followed. Publication happens only after all pages complete. A 410 resets the affected collection's cursor and stages a replacement. Free/busy-only sources use bounded availability requests and protected presentation records.

Create IDs and operation markers are persisted before transmission. Interrupted writes become uncertain and reconcile by identity. Edits fetch current state, compare base/local/remote fields, then use If-Match. RSVP uses the provider's participant-only representation and verifies the self attendee. Structural fields are treated as a coupled group. Conflicts retain local intent until deliberate resolution.

Mutations persist execution state, dependency, request fields, base version, confirmed receipt, and reversal identity. Dispatch revalidates the current operation and source generations after preflight. Coalescing cannot overwrite executing work, and stale callbacks cannot replace newer local intent. A rejected create can be corrected while retaining its provider ID and dependents. Confirmed undo/redo creates conditional compensating writes; deletion recovery creates a new personal draft without guests or conference credentials.

Two accounts may synchronize concurrently; writes use the same calendar gate. A shared HTTP budget allows at most four concurrent requests globally and two per account, with rolling limits of 120 and 60 per minute respectively. These are conservative app budgets, not a promise about Google's quotas. Retry-After pauses and persisted account backoff prevent immediate retry storms. One process owns each store's dispatcher through a file lock. UI refresh triggers coalesce. Current ranges precede bounded month-window prefetch, which pauses in Low Power Mode. Window eviction keeps baseline resources and local work.

AppModel owns sleep/wake, day/time/zone changes, polling, and reminder reconciliation. A local NSViewRepresentable restores reachable macOS 14 window frames. Quit flushes local editor snapshots without waiting for a network response. Reminders are one-shot notifications over cached occurrences; there is no generic repeating notification that could revive a cancelled instance. Search is local, indexed, and guarded against stale query completion.

Production and demo directories are distinct. The demo provider persists its own fictional remote state and supports offline, lost-response, and conflict tests. It is never used to claim that Google integration has passed.

Ordinary OSLog records contain only categories, counts, timings, and operation states. They omit account/event identifiers, titles, raw URLs, guests, and credentials. English UI strings are in Localizable.xcstrings; additional translations are not claimed.
